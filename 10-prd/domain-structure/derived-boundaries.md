# Derived Boundaries

## Source

- derivation source: `../behavior/claims.md`, `../behavior/workflows.md`
- boundary intent: gather source-native information or accept compatible client input without becoming the authoritative reusable memory itself.

## Info-base

- derivation source: `../behavior/claims.md`, `../behavior/rules-and-invariants.md`
- boundary intent: own reusable blocks and relations as the shared memory center.

## Sink

- derivation source: `../behavior/claims.md`, `../behavior/workflows.md`
- boundary intent: retrieve or index info-base information for downstream use without taking over memory authority.

## Application

- derivation source: `../behavior/claims.md`, `../behavior/workflows.md`
- boundary intent: answer a feature, semantic, or graph-navigation request from info-base authority; any index, embedding, or projection remains derived support.

## Extension

- derivation source: `../behavior/capabilities.md`, `../behavior/rules-and-invariants.md`
- boundary intent: add bounded source, resolver, storage, sink, or protocol capabilities through controlled registration and lifecycle hooks.

## Client

- derivation source: `../behavior/capabilities.md`, `../behavior/rules-and-invariants.md`
- boundary intent: represent one runtime participant operating around the shared system.
