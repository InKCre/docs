# 跨 Peer 可观测性契约

本契约定义 InKCre 各 Peer 共同消费的观测身份、传播、持久 Job 因果关联及数据边界。它描述实现应满足的行为，不单独证明当前运行版本已具备这些能力。各 Unit 拥有采集实现，部署 owner 拥有采集出口、存储、查询与保留；SDK 版本、配置、后端限制和验收证据留在相应实现或部署文档。

基础观测与额外 OTLP 出口是两个配置维度。基础观测使用统一记录/查询接口，缺省以内置数据库承接；部署明确选择外部存储后，新采集与当前查询使用该后端，不再强制双写 PostgreSQL。Job 执行开始和终态、已支持操作的摘要不依赖 OTLP 开关。旧记录不删除、不迁移，也不补造历史。

额外 OpenTelemetry 导出与 W3C 上下文采集仍由每个 Peer 的本地配置显式启用，缺省关闭。关闭该出口不关闭基础观测；关闭时不新增 Trace Context 注入、提取或 Job carrier 捕获。原文内容的额外采集权限独立于以上开关。

后端配置在观测实例初始化时形成明确快照，不承诺透明热切换。选择外部但配置不完整、后端不可达或没有就绪的执行 Peer 时，查询明确失败，采集按有界策略报告丢弃，不能静默退回内置存储。观测故障不能使业务 readiness 失败。

## 权威与身份

一个 deployment 保持一个 owner 上下文，已准入 Peer 平等参与。Peer 可以直接操作共享数据库，也可以同步委派能力；观测路径不能强制所有业务绕经某个中心 Peer。[系统状态与权威](system-state-and-authority.md)继续拥有业务 authority。

遥测用于解释已观察的运行，不决定 Job、Agent、图谱或结果的状态。采样、丢失、过期和接收顺序都不能变成业务成功、重试、执行恢复或证据完整性的依据。采集出口与观测后端不可用不应阻止应用就绪或改变业务结果；采集需有界，丢弃需可观察，关闭需有时限。

部署标识、Peer 标识、运行实例与业务 ID 各有意义。部署配置 owner 提供稳定、非秘密的观测部署标识，同一部署的 Peer 与可选采集转发组件使用一致归属；不从凭据、数据库地址或观测产品的项目 ID 派生。重启与原部署恢复保持标识，独立 preview、克隆或新 owner 的部署分配新标识。配置尚不可用的记录可缺少该关联，不能伪造身份或以此阻止启动。

共享部署配置使用 key `inkcre.observability`、schema `inkcre.observability.v1`；value 含 `deployment_id` UUID，以及可选、无凭据的 `otlp_http_endpoints` 对象与 `diagnostics_url`。出口对象按需声明 traces、logs、metrics 的完整 OTLP/HTTP URL；本地启用后缺省信号仍不导出，不要求所有信号共享一个 base URL；共享 value 不携带启用开关。部署启用步骤仅在缺失时创建身份，Peer 不各自生成；私密采集凭据仅从持有凭据的 Peer 运行配置提供，不进入浏览器；浏览器直连需使用适合其公开环境的受限写入能力，否则经过受控转发。凭据不进入该非秘密配置。各 Unit 注册和读取同一 schema；关闭额外 OTLP 的 Peer 不为该出口读取配置或初始化身份，开启时配置尚不可用只暂停该出口。基础记录的后端选择使用独立配置，不依赖 OTLP 身份初始化。

Peer 复用现有身份，运行实例区分各 App 运行期，Job、Thread、ToolCall 与实体保留业务 ID。Trace/Span ID 由标准 SDK 管理，不能用业务 ID 替代。可变业务 ID 适合日志与 Trace 关联，不进入无界指标标签。资源属性用于筛选和诊断，不提供认证或权限证明。

## 同步传播

开启的 Peer 在同步调用中使用标准 W3C `traceparent`/`tracestate`，由所选 OpenTelemetry propagator 负责解析、版本兼容与注入。应用拥有传播目标与 carrier 容量边界，不自行维护 W3C 解析器。自动与手动采集的注入责任应唯一，实际调用使用当时的上下文。

缺失、语义无效或未采样的上下文不改变认证、业务响应、能力选择或执行结果。Trace 解析失败不成为普通 HTTP 业务请求的拒绝理由；不打印原始非法 carrier 作为诊断。同步委派继续遵守[Peer 能力契约](semantic-retrieval-and-peer-capabilities.md)，尤其不能因遥测失败重放结果未知的调用。

传播目标限定在配置的部署边界。对外部模型、Source 或其它服务，默认观察本地客户端调用，不自动携带内部业务身份、上下文或任意 baggage。浏览器、原生 Peer 与进程内 Extension 都遵守此规则；客户端 span 不冒充尚未采集的 PostgREST 或数据库服务端执行证据。

## 持久 Job 的因果关联

Job 的提交和执行可以属于不同 Peer、进程与时间段。公共持久协议提供可选、受限的提交 Trace Context，由开启的创建方在创建 Job 的同一事务中保存；关闭的创建方不捕获该信息并保持缺省 NULL。它属于提交事实，领取和关闭不能将其改写成执行上下文。公共字段为 `submission_traceparent`、`submission_tracestate`，均为可选字符串、缺省 NULL、各最多 512 UTF-8 bytes；数据库协议 owner 交付约束、迁移与各语言投影，不混入 handler 的业务参数或可变执行状态。

512 bytes 是应用持久化容量，不是 W3C tracestate 的全局最大值。创建方保存 SDK 注入的 carrier，超限 optional tracestate 在写入前整体省略并记录有界原因，保留有效 traceparent；不截断成员、不打印原值、不因观测状态重试业务写入。直接输入仍遵守普通类型和容量约束。

Python、浏览器直写及其它直接数据库生产者采用同一提交语义。HTTP 创建入口从当前标准上下文捕获，不要求旧创建 body 接受新遥测字段。Cron 在实际创建一次 Job 时捕获该次发生的上下文，不永久继承最初创建 Cron 的请求。

开启且成功领取的执行器建立独立执行 trace，用 Span Link 连接有效的提交上下文，并在诊断记录中保留同一 Job ID。领取失败不记成实际执行。没有 carrier 的旧 Job 仍可执行；通过普通结构约束但 W3C 语义无效的 carrier 只失去因果 link，不使持久 Job 挂起。关闭额外 OTLP 的执行器不产出标准执行 Trace，但领取和关闭必须保留行中已有 carrier。不同 Peer 的开关可以不同，因而允许提交或执行 Trace 缺失，不影响业务执行。查询可始终按 Job ID 关联，不以提交 trace 仍在保留期内为前提。

普通字段的类型、允许表面和大小边界仍有效；观测容错不意味着接受任意输入。可选字段不自动授予跨版本运行能力。生产者与执行器必须满足[Peer 数据库运行契约](peer-database-runtime-contract.md)的准入要求，交付明确支持的 runtime/schema 组合与顺序；禁止通过写失败后重放 Job 来探测兼容。Job 的领取、取消、终态、timeout 和 Cron 发生语义仍由[知识能力契约](knowledge-capability-contract.md)拥有。

现有 PostgreSQL 日志保留为历史记录，按既有 Job 关联 ID 映射到统一查询。选择外部后，当前查询只覆盖该后端；切换不自动搬迁历史、删除表或改变原日志关联 ID，也不自动退回旧存储读取。没有生命周期记录的旧 Job 只展示真实业务状态，不补写虚构事件。

## AI 诊断与结果证据

模型、embedding、Agent turn、工具调用、检索、Peer 调用和最终结果通过已有业务身份关联。检索候选、实际读取与最终引用或图谱写入是不同事实；某输入与输出存在关联，不足以证明模型依据了该内容或答案正确。

Usage 以 provider 实际返回为依据，覆盖流式结束阶段。未提供、明确为零和非零必须保持可区分；后端估算或补值不能冒充观测事实；允许用最少的字段来源元数据保持区别，缺失标记不作为真实用量参与聚合。成本估算附有价格版本与币种，并与 provider 账单区分；采样 Trace 的费用总和不是完整账本。GenAI 语义约定在实现中固定采用的修订，升级时验证消费兼容。

短期 Trace 可采样、丢失或过期。需要长期复核的证据由对应业务结果 owner 按明确的保存与删除契约持久化，遥测只关联它；不由 tracing 自行引入 Agent 执行库、永久内容副本或确定性回放承诺。

## 内容与访问边界

[共享安全模型](security-boundary-model.md)定义 actor 与权限。这里需要限定的路径是：外部输入或异常携带内容、凭据，经采集写入观测存储，再被超出预期范围的读者或外部运营者取得。Trace Context、Peer/resource 属性及 CORS 均不构成授权。

新增 OTLP 基础模式只采集声明的元数据和关联 ID。Prompt、query、工具参数/结果、引用内容、任意请求响应 body、SQL 参数和异常原文不因打开 tracing 自动获得保存许可；Authorization、Cookie、provider 配置和签名 URL 也不自动采集。基础出口只接入声明来源、字段和值来源的结构化记录，策略覆盖 span 名称、status、events、Resource 与 log body，不能仅过滤 headers 或在远端补做清洗。应用、SDK 和第三方的任意原文日志不得自动桥接到额外 OTLP。基础统一记录也不因选择外部后端自动扩大内容权限；新结构化采集按允许的元数据字段产生固定说明。既有原文日志属于历史，读取它们不宣称已脱敏，存量内容不自动搬往外部。

内容启用独立于基础性能元数据，并明确用途、可访问者、大小与截断、保留和删除。已有 debug 开关不能自动授权向新增观测出口发送内容。删除业务源数据不会天然删除遥测副本，启用内容时必须处理这个差别。

部署 owner 控制摄取与查询入口；采集权限不授予读取或管理权限，浏览器不持有后端管理凭据。对外托管或跨 owner 集中诊断需要明确新增数据边界，不能从非秘密部署标识推导租户隔离。

## 后端可替换性与验证

额外 Trace/指标出口依赖 OpenTelemetry、OTLP，基础记录依赖下述公共语义；业务采集不依赖供应商 SDK、项目或 datasource ID，持久业务 schema/carrier 不保存供应商身份；后端替换应发生在出口配置、存储与消费侧，不要求改写业务采集逻辑。OTLP 兼容不保证历史数据、查询和仪表盘可以无成本迁移。部署交付记录属性映射、必要因果字段、保留或损失的协议信息、导出能力及查询迁移方法；不可恢复的字段损失不能通过默认值伪装成原始观测。

准入应从独立后端查询核对关键字段的可消费语义、缺失与真零、必要因果关联及指标聚合，声明类型投影和损失，并覆盖持久化后的消费。发送成功不算持久化证明。故障验收还需比较真实业务结果，检查应用及可选 Collector 的队列、关闭、丢弃与恢复；只停后端、只测 SDK 或只读取数据库模型不能替代端到端验收。

## 统一记录、查询与执行能力

产品行为由 [可观测性](../10-prd/behavior/observability.md) 拥有。Core 提供记录、查询和存储机制，也拥有标准遥测 SDK 与 OTLP 导出机制；App 持有后端私密配置、装配资源并管理关闭，Web 只消费公共接口。业务代码不绕过 Core 单独连接 OTLP；同一操作的采集入口在 Core 内协调基础记录与按配置启用的标准信号。这里的存储替换边界来自真实的内置/外部消费者，不要求其他 Core 能力统一抽象平台适配器。

非秘密后端选择使用独立配置 key `inkcre.observability.backend`、schema `inkcre.observability.backend.v1`，value 为 `{ "backend": "postgresql" }` 或 `{ "backend": "loki" }`。缺少该记录时使用 `postgresql`；未知 schema 或后端明确不支持，不能视为缺省。原 `inkcre.observability.v1` 的 OTLP 配置形状不变，以兼容严格校验的已发布消费者。

首个双向外部实现为 Loki；其它已配置的日志 writer 或 OTLP endpoint 不能仅凭存在就冒充统一查询后端。Loki URL、认证和租户信息由具备能力的服务 Peer 私密持有，公共配置与浏览器均不携带它们。多个服务 Peer 必须装配同一部署选中的存储；同一公共选择不允许在不同 Peer 上代表不同租户的数据。

各实现通过 `core.observability.v1` 精确 Peer 能力提供 `POST /observability`，沿用已有 Peer 认证、发现与 HTTP 协议。请求包含 `action`：`status`、`query` 或 `ingest`。委派的 `query`/`ingest` 必须附上 `expected_backend`，服务将其与本实例选择原子核对；不匹配返回 409，不把请求写入另一个存储。候选状态探测不能代替这次接收边界检查。数据库模式的调用方可以直接使用已准入数据库协议实现同一接口；外部模式通过具备私密配置的 Peer 执行，业务请求不因此集中到该 Peer。调用者不能指定任意外部 URL、请求头或原生查询语言。

### 公共 JSON

记录 `ObservationRecord`：

- `id`：不透明字符串；旧数据库数字身份加命名空间后投影，不作为跨后端自增序号。
- `timestamp`：带时区的 ISO 时间；`kind` 为 `log`、`event` 或 `span`。
- `severity_number`、`severity_text`：沿用已有 OTEL 1–24 严重度（INFO 9、WARN 13、ERROR 17、FATAL 21），不直接使用 Python logging 的 10/20/30/40/50；`body` 为可展示说明。
- `event_name`、`trace_id`、`span_id` 可为 null。既有 `job.<id>` 关联可继续使用，不将其伪装为标准 W3C Trace ID。
- `attributes` 承载声明的元数据；公共关联键包含 `inkcre.peer.id`、`inkcre.job.id`、`inkcre.operation`、`duration_ms`、`outcome`。时长和用量缺失不补零。`span` 在此表示操作摘要，不承诺完整 Trace 树。

查询 `query` 包含 `since`、`until`、`limit`（1 至 500），可选 `kind`、`severity_min`、`job_id`、`trace_id`、`peer_id`、`operation`、`text`。输入在接收边界校验，时间窗最多 31 天，起点包含而终点不包含，文本不是正则或后端查询语言。结果为 `{ records, truncated, since, until, backend }`，按时间倒序返回。所有过滤由后端语义一致地执行；不先任意截断再把过滤后的子集冒充完整查询。

窗口可能被截断。接口不提供虚假的跨后端稳定 cursor，特别不能用最后一条时间戳跳过同刻记录。界面提示缩小时间或过滤范围；摘要只描述返回窗口，不用于全局分位数、账单或审计计数。

`status` 返回 `{ backend, configured, recording, queryable, scope: "selected_backend", history, dropped, error }`。配置存在不等于网络已验证；`queryable` 表示当前实现具备查询所需配置/能力，实际查询仍可失败。`dropped` 属于报告实例已知的丢弃数，不冒充部署总数；不支持该统计的消费者返回 null。错误使用无凭据、无上游响应原文的诊断。

`ingest` 包含 `records`（最多 100 条，整体最多 256 KiB），返回 `{ accepted, dropped }`；接受表示进入有界处理，不等于已持久化。不得以采集失败重放业务写入。服务需要限制并发、记录大小、元数据容量和关闭时限。

### 生命周期与历史

对象绑定目标部署与后端选择，进行中的写入/查询不随 UI 切换改投另一目标。App 重建实例以采用新配置；Web 忽略旧连接返回的延迟结果。外部后端失败不切换查询源，退出仅释放本实例拥有的队列、连接和任务。

成功领取 Job 后记录开始，完成、失败、超时、取消记录实际终态。观测失败不能推翻数据库已提交的状态，不能把没有记录视为没有执行。采集仅覆盖实际经过已接入实现的执行；旧 Peer 或未采集的信号允许缺失。

Job 提交的持久化结果由数据库 Job 记录拥有，详情从其 `created_at`、当前状态及已保存的 `started_at`、`closed_at` 呈现业务事实。`job.submitted` 等诊断事件独立按有界采集机制写入。提交方退出或诊断写入失败后，其他 Peer 仍可读取已保存的 Job。诊断摘要只使用后端实际返回的 `records`，Job 信息由其持久记录单独呈现。

观测 `timestamp` 使用生产者记录的时间，Job 的数据库时间与各 Peer 的墙钟可能存在偏差。Job 详情的默认时间窗是搜索起点，应用为初始查询提供可解释的余量并支持用户调整。31 天约束每次 `[since, until)` 的宽度，过去的有效绝对窗口同样可以查询。存储保留期属于部署配置，具体记录是否仍可读取以所选后端的实际查询为准。

### Web 消费

全局工作区和 Job 详情复用同一观测查询接口。过滤、关联详情、操作时间线和当前窗口摘要不包含供应商分支。状态面板展示当前存储、配置/能力、历史说明及读取故障；加载、空、错误和截断分别呈现。外部完整 Trace/指标系统可通过已配置诊断入口访问，不用当前窗口的操作摘要假装实现完整 APM。

详情显示已保存的提交事实，以及诊断所用的后端、起止时间和筛选条件。当前窗口只覆盖部分生命周期时，页面说明覆盖范围，并提供调整时间范围的入口。返回记录过多的 `truncated` 提示继续由查询结果驱动。窗口内缺少某个事件时，界面描述本次查询范围内的结果，业务状态继续由 Job 记录提供。

### 变更验证

内置与外部后端使用同一合同样例核对记录、过滤、时间、关联、截断和错误；覆盖配置缺失、未知选择、外部不可用、目标切换和资源关闭。局部模拟传输只证明编解码与控制流，真实持久化、部署路由和跨 Peer 数据读取需要单独的端到端证据。旧合同“始终并行保留 PG writer”的要求由本节替代；数据保留及既有业务协议权限不变。
